# Skill Tester

试用一个技能：不是纸面介绍，而是派一个子代理真实使用该技能处理一条用户请求，主会话再把子代理会话日志里的真实对话和产物整理成对话式试用报告。目的不是评判技能好坏，是让读者亲眼看到技能的作用和实际效果。

角色分工：主会话是「测试设计者 + 报告作者」，子代理是「被测 agent」。子代理只知道技能和用户请求，不知道这是测试，不承担任何测试配合任务（不留痕、不模拟、不汇报元信息）；场景准备和清理都由主会话在派发前完成。

## 流程

1. **了解技能**：细读目标 SKILL.md 及其引用的每个文件（references/、FORMAT 文件、agents/openai.yaml 等）。委托壳（只调用其他技能的）要把被组合技能一并细读。判断执行该技能需要哪些工具权限（写文件、跑命令、浏览器等）。
2. **想好场景**：场景大小跟着用户的测试意图走，默认最小可用。用户 args 里点名的例子本身就是场景：把它翻成一句真实用户的请求即可，不扩写项目背景、不预埋剧情；场景要让技能的关键能力（主要分支、核心产物）有出场机会，不必覆盖全部能力。只有技能执行确实需要上下文（已有代码、路由、数据文件）时，才在输出目录下建 `sandbox/`，且只建需要的部分。确需预埋边角情况时，埋了什么记下来，别靠回忆。沙箱由主会话亲手建好、清干净（残留、半成品、旧 git 状态在派发前处理掉），子代理拿到手的是干净的工作目录。
3. **构造提示词**：提示词只有两段，模板即全部，照抄。args 是用户请求本身，不是主题词：用户说「用 X 为例」，发给子代理的就是「/技能名 X」，不替用户扩写需求、不补充 X 之外的目标。

   ```md
   <SKILL.md 的绝对路径>

   <场景设定的用户请求原话，如「/技能名 参数」；需要工作位置时以真实用户口吻自然写出>
   ```

   子代理的一切行为都应是技能和用户请求的自然结果，场景原话以真实用户口吻书写、不暴露这是测试。
4. **发起子代理**：用 Agent 工具（general-purpose）执行，等它跑完。
5. **写报告**：子代理结束后，主会话：
   - 从子代理会话日志（output 文件，JSONL 格式）提取真实对话：用命令行工具（jq/grep）只取用户消息和助手的**最终总结回复**，不整读日志，防止撑爆上下文；
   - 核对沙箱产物真实存在、与日志中的操作一致；
   - 按下面的模板写输出目录的 `README.md`。技能中「问用户」环节子代理如何自处（默认假设、跳过等），按日志原样呈现并在场景或总结里点一句；
   - 写完自检标点：跑 `grep -nP '[\x{4e00}-\x{9fff}][,;:()]|[,;:()][\x{4e00}-\x{9fff}]' README.md`，有命中就是中文叙述旁残留了半角标点（命中处在行内代码或 md 围栏块内的属正常，不用管），逐处改全角后重跑确认清零再交付。直接编辑写全角字符不可靠时（写完发现仍是半角），用脚本按码位替换：逗号 U+FF0C、冒号 U+FF1A、分号 U+FF1B、括号 U+FF08/U+FF09（Python 里即 `chr(0xFF0C)` 等）。

## 硬规则

- 只写输出目录内部，不动仓库其他任何文件，不 git commit、不 push。
- 中文书写规范：中文叙述一律使用全角标点（逗号、顿号、句号、分号、冒号、问号、感叹号、引号、括号）；代码、命令、路径、错误信息保持半角原样；中文与英文、数字之间留一个空格。模型生成中文时默认偏半角标点，此规范是写后校验的对象而非写时自觉——流程第 5 步的自检是硬兜底，必须执行。
- agent 回复贴原文，不做压缩转述；原文有产物（报告、GLOSSARY、ADR），直接引用产物文件内容。原文是中文叙述的，只把半角标点规范化为全角、其余一字不动——这不算改原文。
- 沙箱零依赖优先；子代理声称跑过的命令，报告里引用的输出必须来自会话日志或产物文件的真实记录，不许口头推演。
- 不虚构对话：报告里的每轮对话必须能在子代理会话日志里找到；日志没有的不写，不编（对话原文的标点规范化除外，见上文硬规则）。
- 对话节只收对话本身：每轮一条用户输入 + 一条 agent 回复原文（交互多轮的取最后一条回复）。中间的工具调用、进度播报、主会话自己的验收过程一律不进对话节——验收结论只在场景或总结里用一句叙述带过。
- 报告用中文：叙述、场景、总结全部中文；agent 回复原文保持原语言，不翻译；代码、命令、路径、错误信息保持原样。
- 报告言简意赅：每句都承载信息，删掉铺垫、重复、客套和空泛评价；回复原文该长则长，自己的叙述部分越短越好。
- 隐私处理：报告里不得出现本机绝对路径、用户名等个人信息，路径一律写成相对路径（产物路径相对于报告所在目录）。
- 总结性文案（场景说明、展示点、总结等）写给人类阅读：语句通顺自然、重点突出，读者扫一眼就懂；不堆术语，不写成流水账。

## 报告模板

输出为单个 `README.md`，结构固定：

````md
# 技能名

> 一句话描述（可自动、仅手动）   ← 复制自技能清单对该技能的描述，英文描述翻译成中文

## 场景

一句话，说人话：这是个什么场景。

## 对话

每轮对话一个列表项，列表项是用户输入，缩进 md 代码块是该轮之后 agent 的回复原文（单轮任务取最终总结回复）：

- /技能名 用户请求原话，一字不改（就是流程第 3 步发给子代理的那句）

  ```md
  agent 回复原文，不转述不压缩。
  ```

## 依赖

可选，无依赖就删掉这节。列出被依赖的技能，每项一句话说清关系：哪个环节用到、拿它干什么；被依赖技能缺失时流程哪一段会断，值得一句。

## 总结

说人话讲清「这个技能是干什么的 + 用起来的实际感受或最明显的局限」，满足两点：

- **浅显易懂**：不用 SKILL.md 里的术语，外行没看过技能，单读总结也明白它有啥用、什么时候会用到；觉得不好懂就借「没装 vs 装了」的对比来讲（没装侧标注「（示意）」）
- **言简意赅**：几句话讲完，不铺垫不重复；流程型技能一句话即可
````
