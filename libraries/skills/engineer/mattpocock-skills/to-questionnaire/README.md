# to-questionnaire

> 把你自己答不了的决策，整理成一份给别人填写的问卷。

## 场景

月底前要决定旧 Jenkins CI 迁不迁 GitHub Actions，关键实情只在维护人老李脑子里，让 agent 生成一份发给老李的调研问卷。产物是 [sandbox/to-questionnaire-jenkins-to-github-actions.md](sandbox/to-questionnaire-jenkins-to-github-actions.md)，14 题，每题带填写占位符，并写明了截止日期和「部分作答、不知道也是有效答案」的填写说明。

## 对话

- /to-questionnaire 我月底前要决定旧的 Jenkins CI 迁不迁到 GitHub Actions，很多关键情况只有现在维护 Jenkins 的老李最清楚，帮我做份问卷发给他，问卷文件放到 questionnaire-sandbox 目录下

  ```md
  这个 skill 的流程是先“盘问发送方”（确认收件人和要拿回什么），再写问卷。本次是无人值守执行，收件人和目标都已明确，我据此直接推断：

  - **收件人**：老李 —— Jenkins 现任维护人，掌握文档里查不到的运行实情
  - **要拿回的**：支撑“迁/不迁”月底决策的关键事实 —— 活任务清单、迁不动的东西、继续留着的代价、他本人的建议

  现在创建 sandbox 目录并写问卷。
  问卷已完成：`to-questionnaire-jenkins-to-github-actions.md`

  **做法**：skill 要求先盘问发送方再写，本次无人值守，我按已知信息推断——收件人是老李（Jenkins 现任维护人，掌握文档外的隐性知识），要拿回的是支撑月底迁/不迁决策的关键事实。问卷全文中文，按“最重要优先”排序并分主题成组。

  **结构**（14 题，每题带填写占位符和"why this matters"）：

  - **Jenkins 现状**：活跃 job 清单、cron/外部触发、顺带挂着的非 CI 任务、使用方范围
  - **迁移的拦路虎**：迁不动或难迁的 job、Jenkins 特有插件/内网资源依赖、凭据存放与知情范围、“连自己也说不清”的黑盒环节
  - **继续留着的代价**：环境健康度与近期故障、未来三年的维护投入预估、停维护/有安全风险的插件版本
  - **你的建议**：整体迁/不迁/部分迁及理由、部分迁的先后取舍
  - **还有别的吗**：兜底问题

  **两点已内置**：截止日期暂填 11 月 20 日（留一周汇总，月底决策）；“不知道”被明示为有效答案。张华斌署名和截止日是推断值，发出去前可直接改。
  ```

## 总结

你面对一个要拍板的决策，但关键信息攥在别人手里——比如系统只有某个老同事维护过，文档里查不到。这个技能不帮你猜，而是把「你需要从他那儿知道什么」整理成一份可以直接发出去的问卷：问题按重要性排序、每题解释为什么问，还明示对方「答不知道也可以」，避免问卷发出后被敷衍或石沉大海。

用起来它有个固定动作：先反过来盘问你本人（发给谁、要拿回什么），再动笔写。本次无人值守，agent 从请求里自行推断出这两点并明说了假设——署名和截止日期都是它暂填的，报告里也提醒发出去前改一下。交互式使用时这两步由它当面问你，比无人值守更贴合真实需求。
