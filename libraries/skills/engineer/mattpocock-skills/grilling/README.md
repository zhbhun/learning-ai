# grilling

> 对用户的计划、决定或想法展开毫不留情的连环拷问，直到达成共享理解。  ← 原文：Grill the user relentlessly about a plan, decision, or idea. Use when the user wants to stress-test their thinking, or uses any 'grill' trigger phrases.

## 场景

用户想给尚未建起来的 Astro 静态博客加评论系统，让 agent 把这个决定拷问清楚。拷问分轮进行、每轮停下来等用户回答，本次试用中由主会话代用户作答、均采信 agent 的推荐答案；agent 自查发现「我的博客」并不存在后，把「博客尚未建、生成器是否已定」摆回台面重新确认。

## 总结

grilling 干的事：你说出一个打算，它不急着动手，而是把这个决定拆成一棵问题树，一轮一轮追问，直到每个分支都有了明确答案、再没有默认假设为止。每轮把当下能问的问题一次性全摆出来，每问都附推荐答案，你逐条认可或纠正即可；该它自己查的事实（本机有没有现成代码、域名注册与否）它自己派子代理去查，不拿来烦你。

用下来两点最明显。一是它不顺着不存在的前提编：请求里说「我的 Astro 博客」，它先扫一遍本机，确认博客根本没建，就把「生成器是否已定」翻出来重新问，而不是假装博客存在往下走。二是问题顺序有讲究：域名卡着部署平台和国内可达性两个下游分支，它压到前两轮落定后才问，避免问出依赖未知答案的问题。局限：它只产出对话，不落任何文档或代码，拷问出的结论要靠后续会话去执行。
