# prototype

> 构建一个一次性原型来回答设计问题。用户想验证状态模型或逻辑是否合理,或想看看 UI 该长什么样时用。

## 场景

用户想做一个 todolist,让技能探索这个页面该长什么样。

## 对话

- /prototype 做一个 todolist。工作目录用 sandbox/

  ```md
  完成原型已建在 sandbox 里，语法检查通过。

  **分支选择**：按 UI 分支（sub-shape B，独立原型页）处理——sandbox 没有既有工程可依附，且"做一个 todolist"默认理解为"它该长什么样"。假设已写进文件顶部注释。
  **产出**：`todolist-prototype.html`
  双击即开，无需任何安装。要点：

  - **3 个结构不同的变体**，不只是换配色：
    - **A 清单列表**：线性列表 + checkbox 勾选，最经典形态
    - **B 看板**：待办/进行中/完成三列，用 ◀/▶ 在列间手动移动
    - **C 按天时间线**：按 今天/明天/以后 分组，点状态标签循环切换
  - **切换**：底部深色悬浮条（‹ ›），或 ←/→ 方向键（输入框聚焦时不拦截），URL `?variant=A/B/C` 可分享、刷新保持
  - **共享内存状态**：四个预置任务在变体间共享，所以切换变体能看到同一份数据的不同呈现；刷新即重置，无持久化
  - **顶部标注 PROTOTYPE** 及问题陈述；无测试、无错误处理，纯 throwaway

  **下一步**：打开后翻一遍三个变体，挑一个（或说"要 B 的布局 + C 的按天分组"这类组合）。选定后按 skill 的 capture 步骤，把胜者沉淀为正式代码、其余移到废弃分支——需要时告诉我。
  ```

## 总结

一句话:把「做个 X」这种模糊需求变成三个结构互斥、浏览器里翻着挑的变体,挑中哪个再沉淀哪个;适合在写第一行正式代码前快速锁定页面形态,单文件双击即开、零依赖,但 skill 对「装在哪、怎么收尾」的约定依赖真实工程上下文,空目录里只能靠假设自圆其说。
