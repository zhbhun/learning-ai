# grill-me

> 一场毫不留情的访谈，把你的方案或设计打磨锐利（仅手动触发）。  ← 原文：A relentless interview to sharpen a plan or design.

## 场景

用户想给一个还没建的静态博客加评论区，让 agent 把整个方案拷问清楚再动手。拷问分轮进行、每轮停下来等用户回答，本次试用中由主会话代用户作答，均采信 agent 的推荐答案。

## 对话

  ```md
  ➡️ 选 A。个人博客的真实流量下，评论区的价值是低频但深度的读者反馈。

  ➡️ 选 B。但如果你的读者几乎全是程序员，A 更省心。

  ---

  ❓ **Q4** - **读者的网络环境**： 读者主要从哪访问？A. 主要国内（giscus 依赖的 GitHub API 与 Disqus 国内时通时断，基本出局，选型倾向国内可达的 Waline/Twikoo）；B. 主要海外，无所谓；C. 两边都要兼顾。

  ➡️ 选 A。中文博客读者大概率在国内。

  ---

  ❓ **Q5** - **运维意愿与数据归属**： 你愿意为评论区维护后端吗？A. 完全不想碰任何服务，只接受纯静态/纯托管方案（选择面收窄到 giscus/Disqus/托管 SaaS）；B. 接受免费额度的 serverless（Vercel/云函数 + 免费数据库，几乎零维护）；C. 有服务器，愿意自托管（Artalk/Twikoo 全功能）。顺带：评论数据要不要完全归自己（随时可导出、可迁移、不怕服务商跑路）？

  ➡️ 选 B。免费额度足够个人博客，数据在自己库里，比 Disqus 干净、比 giscus 门槛低。

  ---

  ```

  ```md
  ---

  ➡️ 选 B。你已经把“读者在国内”定为前提，github.io 的不稳定会直接伤害互动率，一年 60 块是整个方案里性价比最高的一笔钱。

  ---

  ❓ **Q4** - **评论系统：Waline 还是 Twikoo**： 你的约束（昵称邮箱即评、国内可达、免费 serverless、数据自有）下实际入围的只有两个。A. Waline——Vercel + 免费数据库（Neon Postgres / MongoDB Atlas），有完整管理后台、邮件通知、防刷限流、可加文章浏览量统计，维护活跃；部署时多配几个环境变量。B. Twikoo——同样 Vercel + MongoDB Atlas，部署更简单，管理面板直接藏在评论区里，但维护节奏明显放缓，功能面窄（无浏览量统计）。Artalk 需要常驻服务器，已被 Q5 前提排除。

  ---

  ❓ **Q5** - **评论展示策略**： A. 先审后显（零垃圾风险，但读者评论要等你点通过才可见，直接伤害“交流互动”这个核心动机）；B. 即时显示 + 防线（IP 频率限制 + Akismet/词库反垃圾 + 每条评论邮件通知你，发现垃圾再删）；C. 先开审核模式，等博客有真实流量后再关。
  ```

## 总结

grill-me 是「动手前逼你想清楚」的访谈技能：你说一个计划，它不马上做，而是把方案拆成一棵决策树，每轮把当前能问的问题一次性全抛出来——每题带选项、带推荐答案和理由——你答完它再展开下一层，直到没有遗留假设才罢休。没装它时，agent 收到「加个评论区」大概率直接开写代码，一半选择替你默默做了；装了它，14 个分叉决策被三轮问完，每个默认假设都摆到了台面上。

实际体验最省力的一点是：每问都附推荐答案且理由充分，基本可以无脑采信；该它查的事实（本机有没有博客仓库、域名注册了没）它自己动手查，不推给用户。局限：它是个一行委托壳，真本事全在 grilling 里；访谈产生的定案只存在于对话里，要落成文档得用它的姊妹技能 grill-with-docs。
