# internal-comms

> 按公司惯用格式撰写各类内部沟通文案的资源；凡写内部沟通（状态报告、领导层汇报、3P 周报、公司通讯、FAQ、事故报告、项目进展等）都应使用它

## 场景

技能共四条分支（3P 周报、公司通讯、FAQ、通用沟通），各派一个子代理真实跑一遍：给后端平台组写本周 3P update、给全公司写本周 newsletter、把群里反复出现的三个问题整理成 FAQ、写一条机房停电检修的内部通知，素材都在请求里直接给齐。

## 对话

四条分支各一轮，均为单轮请求一次产出。

  ```md
  已按 3P 更新的固定格式（Progress / Plans / Problems）写好，内容只用你提供的事实，可直接粘贴发送：
  ```

## 总结

写内部周报、公司通讯、FAQ、内部通知这类文案，难的不是写，是记格式：3P 周报固定是 emoji 加 Progress / Plans / Problems 三段、每段一两句，公司通讯是分节加短 bullet、用「我们」口径，FAQ 是一问一答体，其他通知则要先想清受众、目的和语气。这个技能把四类模板都收好了，Claude 判断类型后加载对应指南套着写，四轮演示出来全是可发送的成品。

四轮跑下来最一致的体验是「不编造」：素材给齐就照实写；缺什么就明说——newsletter 没给链接就留占位并逐个列出对应关系，FAQ 没给官方答案就标「需补充官方口径」并提醒发布前找 HR、行政、财务补齐，通用通知缺检修时段就注明待补充。另一个共同点是模糊时间会被推算成具体日期（「本周」「下周六」都算出了具体区间），且每次都在回复里主动披露这个假设。局限也明确：指南预设能从 Slack、邮件、日历拉素材，公司通讯建议 20–25 条 bullet，只有零星素材时产出就偏短，想要丰满就得像它建议的那样平时攒各团队的周报当素材。
