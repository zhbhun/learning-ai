# xlsx

> 凡电子表格文件（.xlsx/.xlsm/.csv/.tsv）是任务的主要输入或产出时使用：读取、编辑、新建、格式转换、清洗杂乱数据（自动、仅手动）

## 场景

让 agent 从零做一份带公式的季度预算表，看它按技能走完「建表 → 公式与格式规范 → LibreOffice 重算校验 → 数值核对」的完整流程。

## 对话

- /xlsx 在 libraries/skills/engineer/anthropics-skills/xlsx/sandbox 目录里做一份 2026 年第一季度部门预算表：按月分列（1 月、2 月、3 月），费用项包括人员工资、房租、差旅、软件订阅，要有每项小计和每月总计，用公式算。

  ```md
  数值全部核对无误。任务完成。

  ## 完成报告

  **产出文件**
  - `sandbox/2026Q1部门预算表.xlsx`
  - `sandbox/build_budget.py`（生成脚本，可改数字重跑）

  **表格结构**（sheet：部门预算，Arial 字体）
  - 按用户指定的费用项 4 行：人员工资、房租、差旅、软件订阅；列：1月 / 2月 / 3月 / 季度小计
  - 每项小计 `=SUM(B3:D3)` 式公式；每月总计行 `=SUM(B3:B6)` 式公式；右下角 E7 为季度总计，共 8 个公式，全部公式计算、无硬编码结果

  **遵循技能规范**
  - 蓝色字 + 黄色底标注可编辑的预算输入，黑色为公式；表格底部有说明文字标明假设来源（示例数字，可直接修改）
  - 金额格式 `¥#,##0`
  - 用 `recalc.py`（LibreOffice）重算：`status: success, total_errors: 0, total_formulas: 8`
  - 读回缓存值逐项核对：如差旅小计 35000（12000+8000+15000）、每月总计 115000/111000/118000、季度总计 344000，均正确

  **环境备注**：本机原本没有 LibreOffice，recalc 无法运行，已通过 `brew install --cask libreoffice` 安装后完成重算验证。
  ```

## 依赖

- openpyxl：建表引擎，技能声明预装、本机已有，写脚本直接 import 即用。
- LibreOffice（soffice）：`recalc.py` 重算校验的唯一后端，缺它「零公式错误」这个强制验收环节就断——本机原本没有，子代理现场 brew 安装后才走通闭环。
- pandas / markitdown：批量读表和快速查看用，从零建表的场景未用到，本机也未装，不影响本次流程。

## 总结

这个技能管的是「让 agent 产出的 Excel 是活的、且公式算得对」。没它时，agent 很容易把 Python 算好的总数直接写进单元格——看着对，但改任何输入数字表格都不重算，成了死表；公式还可能随手用上太新的函数，在别的软件里直接变成 #NAME? 错误（以上为示意）。装了它之后，建表守一套硬规矩：公式代替硬编码结果、只用兼容性好的函数、蓝色输入黑色公式黄色假设的分色标注、假设来源写进表格说明；写完必须过 recalc——LibreOffice 把每个公式真算一遍，报出任何公式错误。而且技能专门警告「重算零错误只证明公式能算，不证明算得对」，本次子代理就照这句把 8 个公式的结果读回逐项核对后才交付，产物经独立复核全部属实。

最明显的局限：技能默认跑在预装 openpyxl、LibreOffice、markitdown 的沙箱里，本机只装了 openpyxl，强制环节 recalc 依赖的 LibreOffice 得现场 brew 安装（约 700MB）——技能里越核心的环节，对环境的依赖越硬，换台裸机器第一件事就是补环境。
