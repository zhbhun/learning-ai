# pptx

> 只要涉及 .pptx 或 .potx 文件——创建演示文稿、读取提取内容、编辑修改——都应使用此技能。

## 场景

模拟一位团队负责人要一份 3 页的季度回顾简报，看 agent 从一个空目录起步，用这个技能走完「生成 → 结构校验 → 渲染目检 → 修复」的完整流程。

## 对话

- /pptx 在 libraries/skills/engineer/anthropics-skills/pptx/sandbox 目录里做一份 3 页的团队季度回顾简报：标题页、本季度关键数据、下季度计划

  ```md
  完成。3 页团队季度回顾简报已生成并通过全部 QA。

  **产出文件**
  - `sandbox/2026-Q3-团队季度回顾.pptx`
  - 生成脚本：同目录 `gen_review.js`（pptxgenjs，需 `npm install` 后 `node gen_review.js` 重新生成）

  **页面内容**（16:9 宽屏，Midnight Executive 藏青 + 珊瑚红点缀，圆角卡片 + 彩色序号圆为贯穿视觉主题）
  1. **标题页** — 深藏青底 + 半透明圆装饰，团队名、季度、议程、日期
  2. **本季度关键数据** — 三个大数字统计（86 需求 / 24 发布 / 92% OKR），左下月度需求吞吐柱状图（原生图表，7/8/9 月 26→29→31），右下季度亮点卡片（4 条 bullet）
  3. **下季度计划** — 四张编号卡片（稳定性专项 / 交付提效 / 会员体系上线 / 团队建设），每卡 4 条要点，底部关键节点日期行

  **QA 情况**
  - `validate.py` 结构校验通过（三轮均 PASSED）
  - 内容核对无遗漏、无占位文本
  - 视觉 QA 修了两轮：亮点卡片留白过多（补 1 条亮点）、计划卡片过高显空（收短卡片并各补 1 条要点）、卡片间距从 0.23“ 调到 ≥0.3”

  **环境说明**：本机无 LibreOffice/markitdown，视觉 QA 用的是 WPS Office 的 CLI（`wpscli ppt2pdf`，本机可用）+ `pdftoppm` 渲染逐页检查；内容 QA 用 python-pptx 代替 markitdown。临时渲染文件已清理，桌面无残留。
  ```

## 总结

这个技能解决的问题是：让 agent 产出的 PPTX 文件真正打得开、不报损坏，而且不难看。没有它时，agent 手写幻灯片 XML 极易生成 PowerPoint 直接拒绝打开的文件，用 python-pptx 又只能一行行摆坐标、做不出像样的设计（以上为示意）；装了它之后，agent 按任务选路线——新建演示文稿就写 pptxgenjs 脚本，改现有文件就走解包改 XML 再打包——技能把所有「一写就坏」的坑提前列明（十六进制颜色带 # 会损坏文件、堆叠图的数据标签位置写错也会损坏文件等），还附了一套配色、版式、字号规范，最后强制走 QA：结构校验脚本逐项检查并给出修法，再渲染成图片逐页目检、修完复检。本次 3 页简报就是走这条流水线出来的：两轮视觉修复（留白、间距）后定稿。

最明显的局限：技能假设运行在预装好 pptxgenjs、LibreOffice、markitdown 的沙箱里，普通本机缺这些时体验打折扣——本次子代理现场 npm install 了 pptxgenjs，LibreOffice 和 markitdown 本机没有，它自行改用 WPS 的命令行转 PDF 做视觉 QA、用 python-pptx 做内容检查，QA 闭环照样走通，但换台机器这类替代方案未必存在。
