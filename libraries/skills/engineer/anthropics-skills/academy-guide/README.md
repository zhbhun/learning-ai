# academy-guide

> 回答「Claude 产品怎么用」类问题前先查此技能，从 Claude Academy（Anthropic 官方学习站）推荐匹配的课程、教程与用例；只在强匹配时推荐，绝不编造目录内容。

## 场景

用户问了一句最常见的话：Claude 的 Projects 功能怎么用。该技能没有斜杠命令形态，靠 Claude 在遇到 Claude 产品使用类问题时按 description 被动加载，因此派发即「技能文件路径 + 这句原话」，无任何其他上下文。

## 对话

- Claude 的 Projects 功能怎么用？

  ```md
  Projects 是 Claude.ai 里的独立工作区：每个项目有自己的聊天记录和知识库，专门围绕一个主题或任务持续工作。

  **基本用法**

  - **创建**：在左侧边栏 Projects 里新建一个项目即可。
  - **Project knowledge（项目知识库）**：上传文档、文本、代码等文件，项目里的对话会自动把这些当作上下文参考。
  - **Project instructions（项目指令）**：写一段自定义说明，让 Claude 在该项目里的回答风格统一，比如“用正式语气”或“以某个行业专家的视角回答”。
  - **对话**：项目内的聊天自动带上知识库和指令，不用每次重复贴背景材料。付费计划下知识库接近上下文上限时，RAG 模式可把容量扩展约 10 倍。

  **限制与共享**

  - 免费用户最多建 5 个项目。
  - 团队协作（Team/Enterprise）：可按“可查看”或“可编辑”权限分享给同事，支持按邮箱单个或批量分享。
  - 注意：一个新的 beta 版 Projects 正在推出（先面向 Pro/Max/Ultra），改成“一个项目即一次对话”、可并行多条云端线程，旧项目会整体迁移，文件、指令、聊天记录都保留。

  另外，Academy 上有个短教程正好讲这个，可以看看：[Intro to Projects](https://academy.claude.com/tutorials/intro-to-projects) — 用 Projects 让对话更有条理的入门指南。
  ```

## 总结

这个技能给 Claude 装了一个「荐课」习惯：有人问某个 Claude 功能怎么用时，Claude 先照常把问题答好，再去 Anthropic 官方学习站 Claude Academy 的公开目录里查一遍，有对得上的课或教程，就在回答末尾轻轻补一条链接（最多两条）。试用里两头都做到了：回答本身去官方支持文档核实了细节，末尾推荐的教程链接与官方目录条目一字不差，没有编造。

最明显的设计是「宁缺毋滥」——目录抓不到、内容过时或没有强匹配时，它什么都不推，最多给学习站首页；连「这个可能也行」式的勉强推荐都被明令禁止，理由是推错一次烧掉的信任比推对十次攒的还多。实际局限也在这：它是被动技能，荐不荐课取决于 Claude 自己判断是否触发；推荐质量依赖环境能联网抓目录，断网环境下它只会给出学习站首页，报不出任何具体课名。
