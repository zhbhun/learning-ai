# frontend-design

> 构建新界面或重塑现有界面时，提供有辨识度、有主见的视觉设计指导；涵盖美学方向、字体排印，让设计不落入模板化的通用默认

## 场景

用户经营一间老城区二手书店，要一个单页宣传网站。工作目录是空沙箱（下文写作 `sandbox/`），没有品牌、素材等任何预置材料——技能本身就设计为从一句需求开始做设计。

## 对话

- /frontend-design 为我经营的一家老城区二手书店做一个单页宣传网站，产出文件保存到 libraries/skills/engineer/anthropics-skills/frontend-design/sandbox 目录下

  ```md
  整页确认完毕，桌面端、移动端（390/320px）均无横向溢出，渲染成立。任务完成。

  ## 完成报告

  **产出文件**：`sandbox/index.html`（单文件，含全部 CSS，无构建依赖）

  **设计方案**（按 skill 两段式流程，先规划后自检再实现）：
  - **题材锚点**：从中国旧书业实物取材——线装书函套布面色、朱砂藏书印、书脊题签、读者批注，而非泛泛的“复古风”
  - **色板**：陈纸 `#EAE3D2`、墨 `#26231D`、朱砂 `#B23A26`、墨绿布面 `#22453A`、藏青 `#2E3D55`、赭石 `#5E2A22`
  - **字体**：Noto Serif SC（正文）+ 霞鹜文楷（批注、题签的手写感）
  - **记忆点（boldness 集中一处）**：首屏右半是一面书脊墙——五个区块入口做成竖排书脊，高度错落、布面色不同，载入时依次“插上架”，悬停如抽书；店名做成竖排题签配朱砂印（印文按传统右起“书拾局遗”排布）

  **页面结构**：这间店（简介）、来路（斜贴老照片 + 年表）、批注（胶带便签式旧书批注，左右交错）、架上（竖排书脊标签的四架分类）、来店（竖排“欢迎来坐”签 + 营业时间/交通）

  **自检与修正**（对照 skill 列出的 AI 默认特征）：
  - 初稿文案踩了“间隔号串联元信息”和带空格破折号的 tell，已全部改为中文自然标点
  - 首屏书脊墙初版偏小插画感，加密加高成真正的“一面墙”
  - 修复“星期二至五”固定列宽导致的折行；修复移动端 203px 横向溢出（窄屏分级隐藏装饰书脊，320/390px 均已验证溢出为 0）
  - 质量底线：响应式至 320px、键盘焦点可见、`prefers-reduced-motion` 下关闭载入动画与平滑滚动

  浏览器截图自检（ego-browser）已完成桌面与移动两档验证，最终整页渲染成立。
  ```

## 依赖

- ego-browser：技能要求「环境支持时截图自审成品」，本次自检靠它发现首屏比例失当、移动端横向溢出等硬伤；缺失时技能仍能完成，但少了「以图审图」的打磨回路。

## 总结

frontend-design 是给「做个网页/界面」这类请求配的一位有主见的设计总监。它要求先交设计方案再写代码：定下色板、字体和版式概念，然后拿一份「AI 生成页面的俗套特征清单」（奶油底配赤陶色、全大写眉题、间隔号串联元信息、清一色圆角卡片之类）逐条对照自查，确认自己的方案不是「任何题目都会做出的那个默认答案」，才动手实现。

试用感受是自查环节真实起效：子代理的初稿文案就踩了技能点名的「间隔号串联元信息」俗套，自己改掉了；首屏书脊墙第一版嫌小插画感，自己加密加高成整面墙；最后用浏览器截图逐屏检查，修掉移动端 203px 横向溢出才收工。最终成品的辨识度确实不在通用 AI 风——设计从中国旧书业实物取材：布面函套的墨绿藏青、朱砂藏书印、竖排书脊墙，连店名印文都按传统右起排布。技能中「题材不明时先与客户确认」一条，本例因题材明确未触发，美学方向由子代理直接自行决定。

局限：一次调用不便宜（本例约半小时），且它只负责「这页面长什么样、说什么话」，不含任何业务功能；效果是视觉判断，建议拿到成品后自己打开浏览器过一遍。
