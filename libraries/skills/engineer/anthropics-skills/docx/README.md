# docx

> 创建、读取、编辑 Word 文档（.docx/.dotx）：凡提到 Word 文档、.docx、或要求产出带目录、标题、页码、信头等专业排版的文档时使用（自动、仅手动）

## 场景

把一段口述的会议记录整理成一份专业排版的正式 Word 文档。

## 对话

- /docx 帮我把这份会议记录整理成一份正式的 Word 文档，输出到当前目录下的 meeting-minutes.docx：标题「项目周会会议纪要」，日期 2026 年 11 月 6 日，参会人张伟、李娜、王强；下面分三个小节：一、本周进展（移动端 App 完成登录模块联调，后台服务接口联调完成 80%，测试环境已部署）；二、存在问题（接口文档与实际实现不一致，测试环境数据库连接偶发超时）；三、下周计划（完成剩余接口联调，启动集成测试，输出测试计划初稿）。请做出专业排版的文档。

  ```md
  完成。文档已生成并验证。

  **输出文件**：`sandbox/meeting-minutes.docx`（约 10 KB）

  **做法**：按 docx 技能指引，用 docx（npm）脚本创建（`docx` 包默认不可解析，按技能说明安装到了临时脚本目录）。

  **文档内容与排版**：
  - 居中大标题「项目周会会议纪要」（44 half-point，黑体/Arial 加粗）
  - 标题下居中信息行：会议日期 2026年11月6日、参会人员张伟、李娜、王强，带灰色底部分隔线
  - 三个小节标题（一、本周进展 / 二、存在问题 / 三、下周计划），使用 Heading 1 样式（黑体加粗、outlineLevel 已设，可出现在目录中）
  - 各节条目为规范的项目符号列表（通过 numbering 配置的 `LevelFormat.BULLET`，非字面 •）
  - 中文正文宋体 + 西文 Times New Roman，小四（12pt），1.5 倍行距，A4 默认页面，四周 1 英寸页边距

  **验证**：环境无 LibreOffice（soffice）和 pandoc，无法按技能的 PDF 渲染流程做视觉检查；改为解包 docx 验证——全部 14 条文本内容完整无误，项目符号引用正确（16 处 numPr），document/numbering/styles 等 XML 均通过格式校验。如需视觉确认，可在 Word 中直接打开查看。
  ```

## 依赖

- docx（npm 包）：创建新文档的引擎；技能说明它预装、require 失败时才 npm install——本次环境正是走了这条 fallback。
- LibreOffice + pdftoppm：写完文档后渲染成 PDF 再转图片做视觉验证；本机两者皆缺，该环节退化为解包 XML 核对。
- pandoc：读取已有 docx 内容用；本机未装，本场景只创建文档，未受影响。

## 总结

没这个技能，agent 生成的 Word 文档排版随缘，还要自己踩 docx-js 的坑（列表符号、表格宽度、分页符等处处是陷阱）。装了之后，新建走 docx-js 脚本并按技能清单避开全部已知排版坑，编辑已有文件走解包 XML 改完再打包，读取走 pandoc，写完还强制「渲染成图片亲眼检查一遍」。本次试用生成很顺：一段会议纪要直接产出带标题样式、规范项目符号、中英文字体区分的正式文档。最明显的局限在验证环节——本机没装 LibreOffice 和 pandoc，技能要求的视觉检查做不了，子代理只能退化为解包 XML 核对内容，排版是否真如描述得靠人打开 Word 确认。
